# M2 · D2(b) — the v1 → v2 rewrite, and what it changed (measured offline; live pass rates to follow)

**v1** = the vendor scaffold as shipped (commit d1aad0c): `A2_scaffold/tools.py` + `A2_scaffold/prompt.py`.
**v2** = this commit. Only those two files carry the rewrite; `agent.py`, `guardrails.py`, the cases and the answer key are untouched, so a v1/v2 run differs in ONE thing. `A2_live_battery.ipynb` cell ③b reverts exactly these two files to d1aad0c for the v1 pass.

## What v2 changes

### 1. Six-field descriptors with a size bound (D2(b) requirement)
Every Problem-A tool now carries NAME+SIGNATURE / WHAT / WHEN / INPUT / RETURNS / SIZE BOUND / FAILS WHEN / IRREVERSIBLE?. v1 had no signature, no size bound and no irreversible field; `issue_decision_letter` is now the only tool marked IRREVERSIBLE: YES, pointing at the autonomy gate.

### 2. The routing rules name the exact trigger strings
v1's prompt described the escalation reasons in prose and never showed the strings the answer key grades on. M1's live run (gpt-4o-mini, 15 Sep) lost most of its 24.2% to `lapsed` vs `policy_lapsed`, `date_of_service` vs `outside_policy_dates`. v2 lists the five triggers verbatim, gives a check order with early exits, and states which fields the final record must carry per outcome.

### 3. "JSON only" is stated as a hard rule
claude-haiku-4.5 answered the final step in prose under v1 (M6, 17 Sep). v2's HOW TO ANSWER says the entire reply is one JSON object, no fences, no prose, and that anything else counts as a failed run. (The live backend separately forces JSON per vendor and has one repair call — that is harness, not prompt, and is identical in both passes.)

### 4. Two poka-yoke moves — what each makes IMPOSSIBLE
| Before (v1) | After (v2) | What it makes impossible |
|---|---|---|
| The model compares `documents[]` against a rule it was never given | `get_claim` returns `missing_documents[{document, for_line}]`, computed in code from `required_documents.json` (file extensions normalised) | Mis-comparing "itemised_bill.pdf" with "itemised_bill", or not knowing which line needs which document. Checked against all 48 cases: exactly the 4 answer-key `request_document` cases are flagged, no false positives. |
| `issue_decision_letter(decision: str)` accepts anything, including `"escalate"` | `decision: Literal['approve_in_principle','request_document']`; anything else returns `{sent: false, error}` and records nothing | A typo'd decision being recorded; an escalation being "sent" to the member. |

Plus one robustness fix in the same file: a wrong argument name or shape used to raise (`TypeError` / `ValueError` / `KeyError`) out of the loop and kill the whole `--all` battery; it is now an error observation naming the correct signature, so the run is graded on its outcome. An unknown tool NAME still raises as before, and agent.py turns that into a safe escalate.

### 5. The measured return-shape rewrite (lever 3, observation size D)
| Tool | v1 return | v2 return | chars per call (repr) |
|---|---|---|---|
| `lookup_policy` | `{member: {member_id, name, policy_id, join_date}, policy: {...}, remaining}` | `{member_id, policy: {...}, remaining}` — the member row carries no decision information | 442 → 354 (−20%) |
| `check_duplicate_claim` (hit) | the whole prior history row | `{duplicate_of, decision, decided_on, matched_on[4]}` | 214 → 164 (−23%) |
| `get_claim` | claim row | claim row + `missing_documents` | 395 → 420 (+6%, deliberate) |

## What v2 costs (lever 1, tool block B) — reported honestly
`python3 run_eval.py --prompt`: v1 6,243 chars ≈ 1,561 tokens; **v2 9,311 chars ≈ 2,327 tokens (+49%)**. The prefix is re-sent every turn, so at a median of 4 turns v2 adds ≈ 3,100 input tokens per run (≈ US$0.003 on claude-haiku-4.5, ≈ US$0.0005 on gpt-4o-mini). One avoided escalation (US$7.60) pays for ~2,500 runs of that overhead, so v2 is worth it if it moves the pass rate at all — which the live v1/v2 pass on one model is there to measure.

## Scripted check
`python3 run_eval.py` on this commit: 40 scripted cases, 88/88 PASS (unchanged — the scripted backend never reads the prompt).
