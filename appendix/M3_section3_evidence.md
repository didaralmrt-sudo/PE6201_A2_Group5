# Section 3 — Evaluation evidence (M3 draft)

The committed fixture set contains 48 Problem A claims: 15 supplied cases and 33 team-authored cases. The default scripted run currently covers 40 of them (seven supplied and all 33 team-authored). Each case starts with a fresh agent state. The harness compares the recorded decision with an independently authored answer key and also checks the trigger for escalation cases. It prepares a separate `must_record` queue for human or second-model judgement; that queue is not automatically graded.

On the committed `BACKEND = "scripted"` setting, `python run_eval.py` passed **88/88 trials (100%)** across the 40 scripted cases. Non-act outcomes received three trials each. M3's seven cases accounted for **17/17 passing code-check trials**, including lapsed cover, duplicate claim, an injected instruction in a member narrative, and an out-of-window service date. We reviewed the M3 first-trial reasons against the `must_record` requirements and made the duplicate, injection and policy-date explanations more explicit. The scripted backend replays fixed model moves, so this result verifies wiring and grading; it does not measure live-model reliability. The run reports US$0.1503 of simulated token cost, with no API charge.

The only live result documented in the repository so far is M1's earlier `openai/gpt-4o-mini` run: **8/33 trials (24.2%)**, 219,543 tokens and US$0.0243. It used the earlier 15-case set, so it is not a like-for-like comparison with the current 40-case scripted result. Reported failures include trigger-label mismatches, invalid tool names and missed prompt-injection triggers. M3's Meta Llama run and the remaining model battery are still pending; a cross-model pass-rate table should be added only after those runs are measured on the same fixed set.

Eight supplied claims still have no scripted replay, so `python run_eval.py --all` is not the reproducibility command. The no-key marker command is `python run_eval.py` from `A2_scaffold/`.
